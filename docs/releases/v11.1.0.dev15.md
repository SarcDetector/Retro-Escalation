# RE-OSCR 11.1.0.dev15

Dev15 is a Command Console-only technical preview of source-audited CLA v1.4 Damage Out
calculations. It runs from the immutable event set selected by OSCR, keeps OSCR as parser truth,
and records stable snapshot and result provenance. The preview is intended to give Raman and other
testers an inspectable first slice while its independent golden-fixture evidence is still pending.

## Technical preview scope

- Adds stable snapshot identity and result provenance for the OSCR-selected combat event set.
- Exposes the CLA v1.4 preview only in Command Console and only for an unmodified parser-truth
  Analysis view.
- Implements the preview clock contracts `TIME-01`, `TIME-02`, `TIME-03`, `TIME-04`, `TIME-06`,
  and `TIME-09`.
- Implements Damage Out metrics `DO-01`, `DO-02`, `DO-04`, `DO-06`, `DO-09`, `DO-10`, `DO-16`,
  and `DO-17`, with all/shield/hull values where applicable.
- Provides **COPY RAW REPORT** so testers can capture the calculated values and their provenance
  without treating formatted table cells as oracle data.

The implementation is source-audited against CLA v1.4 behavior, but its golden fixtures are not
complete. Dev15 is therefore a technical preview, not a numerical-parity certification.

## Deliberate limits

- Modified Workbench views cannot use this preview. Resetting to parser truth is required.
- Dev15 does not ship complete CLA parity, a selectable CLA calculation profile or profile
  selector, CLA hierarchy, flag metrics, Damage Out graphs, or the remaining Damage Out metrics.
- Player-root preview totals are accumulated in frozen event order. Exact CLA hierarchy aggregation
  traversal/order is still pending; because binary64 addition is not associative, arbitrary-decimal
  real-log sums and dependent metrics may differ at the bit level. This is a known preview boundary,
  not a parity tolerance.
- Damage In, Healing Out, Healing In, summary-copy parity, formatting parity, and other CLA
  analysis directions are not included.
- Preview results are display-only derived analysis. They cannot become a League upload
  source and do not alter OSCR parser truth or League upload coordinates.
- Legacy is unchanged and does not expose the preview.

The rounded preview table is display convenience, not an oracle. **COPY RAW REPORT** is the stable
comparison surface for dev15 because it includes unrounded values and snapshot/result provenance;
it remains subject to the aggregation-order limitation above.

## Raman and tester handoff

1. Open the target log in RE-OSCR and select the same OSCR-selected combat used for the CLA v1.4
   comparison.
2. In Analysis, use **Workbench Reset** and confirm the view is parser truth with no filters, time
   cuts, or rules active.
3. Open the Command Console CLA v1.4 Damage Out preview and use **COPY RAW REPORT**.
4. Provide permission to retain the test log, the exact log-file hash, and the raw CLA v1.4 oracle
   output for that same selected combat.
5. Attach the RE-OSCR raw report and record the RE-OSCR build or commit, operating system, selected
   combat, and any observed difference. Redact player handles before sharing material publicly.

The first acceptance target is reproducible agreement for only the clocks and Damage Out metrics
listed above on the same OSCR-selected event set. Differences are useful preview findings; they do
not establish that OSCR selected the wrong combat or authorize changing parser-owned data.
