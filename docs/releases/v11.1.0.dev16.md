# RE-OSCR 11.1.0.dev16

Dev16 turns the CLA v1.4 Damage Out preview into a complete scalar-analysis coprocessor for the
OSCR-selected combat. It adds Summary, Damage In, Heal Out, and Heal In; completes all Damage Out
columns; and exposes CLA's default expandable hierarchy in one tester-facing Command Console
window.

## Math coprocessor scope

- Calculates the five comparison surfaces: **Summary**, **Damage Out**, **Damage In**,
  **Heal Out**, and **Heal In**.
- Implements all 21 CLA v1.4 damage metric families and all eight healing metric families,
  including all/shield/hull aspects and blank denominator states.
- Implements CLA's player Damage Out and Active clocks, including the one-second floor and
  missing-range sentinel used by rate calculations.
- Reproduces the default direct and indirect hierarchy for all four analysis directions, including
  same-name leaf/branch collision handling and immediate-parent percentages.
- Preserves source-defined edge behavior for immune/zero hits, immune healing, direct self-damage,
  duplicate incoming attribution, shield-critical percentages, kill details, damage-type unions,
  maximum-hit provenance, and the released unsigned non-critical denominator wrap.
- Adds an **ALL / SHIELD / HULL** selector, rounded current-tab copy, complete raw JSON copy,
  and JSON export with immutable snapshot/result provenance.
- Keeps every result display-only and explicitly League-ineligible. OSCR remains the parser and
  combat-selection authority.

## RE-OSCR native Wayland popout

- Adapts Raman's OSCR-UI v11.2.1 layer-shell approach to RE-OSCR's one-parser architecture.
- Keeps the inherited OSCR live parser in the main process. A presentation-only child receives
  normalized rows, combat duration, visibility, and display settings over a private process
  channel; it receives no combat-log or configuration path.
- Uses the isolated layer-shell presentation on supported native Wayland sessions with compatible
  LayerShellQt components. Missing or mismatched native components and child startup/runtime
  failures fall back to the existing in-process popout.
- Leaves Windows, X11, macOS, and the offscreen test platform on the existing popout path.
- Targets KDE Plasma/KWin and wlroots compositors; GNOME/Mutter support is not claimed.
- Treats `pywayland` as an optional drag helper only. pipx testers can request it with
  `pipx install 're-oscr[wayland]'`.
- Documents that pinned `pywayland==0.4.18` has no CPython 3.13 wheel on PyPI. The optional pipx
  extra therefore builds from source and needs GCC, matching Python development headers, libffi
  development headers, and Wayland headers/protocol tools.
- Keeps the embedded preview and browser/OBS browser source on their existing main-process data
  path. The OBS files, websocket feed, and visibility model are unchanged.
- Makes Linux portable-build inclusion of compatible layer-shell components conditional. Builds
  without them retain the normal popout fallback.

## Verification

The public regression suite uses anonymous, exactly representable synthetic events. It covers all
five surfaces, the complete metric manifests, clocks, attribution, default direct/indirect
hierarchies, malformed source edges, raw provenance, and the Qt presentation.

Platform-neutral Wayland contract tests cover support selection, native-library probing, isolated
launch preparation, bounded normalized-row protocol handling, sensitive-path rejection, and
normal-popout fallback. They run under Qt's offscreen platform on Windows and do not require a
Wayland compositor.

The Ubuntu 22.04 portable workflow installs the conservative native prerequisites, installs
`.[pyinst,wayland]`, and imports `pywayland` before packaging. This keeps the CPython 3.13 source
build exercised in CI rather than leaving it solely to pipx testers.

Separately, a private real-combat comparison matched CLA v1.4's displayed player-root Damage Out
clock and all visible scalar columns. The private input and identifying derivatives are not part of
the repository, packages, or public test output.

## Deliberate limits

- CLA rule transforms and CLA graph emulation are not included in this calculation release.
- Modified Workbench views remain blocked. Reset Analysis to parser truth before opening the CLA
  result.
- RE-OSCR uses deterministic hierarchy traversal. Bit-for-bit equivalence with the pinned Rust
  release's internal `HashMap` floating-point aggregation order is not claimed.
- Rounded cells and copied tabs are presentation. **COPY RAW JSON** / **EXPORT JSON** retain the
  unrounded calculation values and provenance.
- Layer-shell placement depends on compositor and compatible native LayerShellQt support.
  `pywayland` adds dragging but does not add compositor support.
- Legacy remains unchanged.
