## Protected authority boundaries

These are release invariants, not implementation suggestions:

1. `STO-OSCR` owns combat discovery, combat boundaries, parsed `Combat.log_data`, map and
   difficulty detection, parser models, and parser-truth results.
2. League uploads use only the parser-owned current combat's source path and byte range. Derived
   display combats do not expose upload coordinates as their own and are never accepted as the
   League source; internal display provenance may still identify the official source combat.
3. Workbench rules, filters, exclusions, and cuts remain display-only. Modified views are labelled,
   and RESET returns the selected combat to parser truth.
4. Legacy remains isolated from Command Console-only presentation and Live services.
5. The Live Control Center uses one inherited live-parser session for its embedded, popout, and
   browser presentations. Hiding a presentation never stops that parser.
6. The dev12 tag and its published files are immutable. Corrections move forward under a new
   version; the tag is never retargeted or replaced.

## Behavior frozen at this checkpoint

- Five Command Console workspaces: Overview, Analysis, League, Settings, and Live Parser.
- Simple and Advanced Analysis presentation over the same selected OSCR combat, or the same
  labelled display-only derived view when modifiers are active.
- Display-only GROUP, REVERSE, and EXCLUDE rules; structured filters; inclusive time cuts;
  modified-view labelling; persistent rule definitions; optional explicit auto-enable.
- Frozen Analysis identity column, synchronized tree state, readable metric lenses, live weighted
  lines, and explicit detailed bars.
- League ladder browsing, local-log loading, downloaded-parse open/save, and parser-owned upload
  behavior.
- Consolidated Settings presentation without removing inherited settings keys.
- One-session Live Control Center, Windows global hotkey, and read-only localhost/private-LAN
  browser feed.
- Automated Windows, Linux, and PyPI release paths.
